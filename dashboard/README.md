# Dr.Orn IT Helpdesk Dashboard — Visual Prototype (DEMO DATA)

ต้นแบบหน้าตา Dashboard สำหรับรีวิว Layout, KPI, กราฟ, ตาราง และตัวกรอง
**ใช้ข้อมูลจำลอง (Mock Data) เท่านั้น** ไม่เชื่อม Google Sheets, Apps Script, LINE, LIFF, Cloudflare Worker หรือ API จริง
การเรียกออกนอกเครื่องมีเพียงอย่างเดียว คือขอไฟล์ฟอนต์จาก Google Fonts (`fonts.googleapis.com`) ซึ่งไม่ส่งข้อมูล Ticket ใด ๆ
ทุกหน้ามีป้าย `DEMO DATA` และ Ticket ID ใช้รูปแบบ `DEMO-YYYYMMDD-NNNN` เพื่อไม่ให้สับสนกับข้อมูลจริง

## เปิดดูในเครื่อง

วิธีที่ 1 (ง่ายที่สุด): ดับเบิลคลิก `index.html` เปิดด้วย Chrome / Edge

วิธีที่ 2 (ใกล้เคียง GitHub Pages): เปิด Terminal ในโฟลเดอร์นี้ แล้วรัน

    python3 -m http.server 8080

จากนั้นเปิด http://localhost:8080/ (ใช้ Python ที่ติดตั้งไว้แล้ว ไม่ต้องติดตั้งอะไรเพิ่ม)

ไม่ต้อง build ไม่ต้อง npm install

## สิ่งที่ลองได้ในหน้า

- ตัวกรอง: Date range (7D/14D/30D/60D หรือเลือกวันเอง, กรองตาม Created At), Branch (แสดงชื่อไทย, ตัวเลือกแรก "ทุกสาขา"), Status, Priority — KPI กราฟ และตารางเปลี่ยนตามกัน
- Hover บนกราฟเพื่อดูตัวเลข, คลิกหัวคอลัมน์ตารางเพื่อเรียงลำดับ, "ดูข้อมูลเป็นตาราง" ใต้ทุกกราฟ
- ปุ่ม Theme สลับสว่าง/มืด
- "Preview states" ที่ Sidebar: Normal / Loading / Error / Empty เพื่อดูหน้าตาแต่ละสถานะ

## การแยก Mock ออกจาก Production

- `app.js` อ่านข้อมูลผ่าน `window.DashboardData.load()` เท่านั้น
- `mock-data.js` ตั้ง `source: 'DEMO'` และ `app.js` (ฟังก์ชัน `checkDemoData`) ตรวจ **ทั้งชุดข้อมูล** ก่อน render อะไรทั้งสิ้น
  ถ้ามีข้อใดไม่ผ่าน (แม้เพียง Ticket เดียว) จะปฏิเสธทั้งชุดและแสดง "Prototype blocked" พร้อมเหตุผลสั้นๆ (ไม่แสดงเนื้อหาของ Ticket)
  - โครงสร้างครบ: `source === 'DEMO'`, `now`, `tzOffsetMs`, `firstDay`, `branches`, `categories`, `priorities`, `statuses`, `slaHours`, `tickets`
  - ทุกสาขาใน `branches` ต้องมีชื่อไทยกำหนดไว้ (สาขาที่ไม่รู้จัก เช่น `Other/Non-branch` จะไม่ผ่านและไม่ถูกแสดง)
  - ทุก Ticket: ID รูปแบบ `DEMO-YYYYMMDD-NNNN` (วันที่ใน ID เป็นวันปฏิทินที่ถูกต้องและตรงกับวันที่ `createdAt`) และไม่ซ้ำ,
    มีครบทุกฟิลด์ใน schema และ **ไม่มีฟิลด์เกิน schema**, `branch/category/priority/status` อยู่ในรายการที่กำหนด,
    `slaDue = createdAt + SLA hours`, เวลาต่างๆ ไม่เกินเวลา Demo, `closedAt` มีก็ต่อเมื่อ `Closed`, `rating` เป็น `null` หรือจำนวนเต็ม 1–5 และมีได้เฉพาะ Closed
  - ชุดข้อมูลที่ถูกต้องแต่ `tickets` ว่าง (`[]`) ไม่ถูกปฏิเสธ จะแสดง Empty state
  - **ข้อจำกัด:** guard เป็นเพียงมาตรการกันการนำข้อมูลมาปะปนโดยไม่ตั้งใจ ไม่ใช่การรับประกันว่าแหล่งข้อมูลเป็นข้อมูลจำลองจริง
    (ใครก็ทำข้อมูลให้หน้าตาเหมือน schema นี้ได้) ความปลอดภัยจริงมาจากการไม่เชื่อมแหล่งข้อมูลจริงและการไม่ใส่ Secret ในไฟล์
- เมื่อถึงขั้นเชื่อมข้อมูลจริง ต้องทำเป็นไฟล์ใหม่ (เช่น `api-client.js`) และปรับ guard ในรอบที่ได้รับอนุมัติเท่านั้น
- ไม่มี Secret, Token, Spreadsheet ID หรือ LINE ID ในไฟล์ใดเลย

## นิยามที่ใช้ใน Prototype (ต้องยืนยันก่อนใช้กับข้อมูลจริง)

| ตัวชี้วัด | นิยามใน Prototype |
|---|---|
| SLA Due | Created At + ชั่วโมง SLA ต่อเนื่อง (Critical 1, High 4, Medium 8, Low 24) — ข้อมูลจริงต้องอ่านค่า `SLA Due` ที่เก็บไว้ ไม่คำนวณใหม่ |
| SLA Breached | ยังไม่ปิด และเวลาปัจจุบันของ Demo เกิน SLA Due |
| SLA Due Soon | ยังไม่ปิด และเหลือ ≤ 60 นาที |
| SLA Status (ตาราง) | ยังไม่ปิด: Overdue / Near Due / On Time · ปิดแล้ว: Met / Missed (แยกสถานะปัจจุบันกับผลลัพธ์) |
| SLA Compliance % | Ticket ที่ปิดทัน SLA Due ÷ Ticket ที่ปิดทั้งหมดในตัวกรอง |
| Response Time | Created → Claimed (median) |
| กราฟ Trend (per day) | Created = จำนวน Ticket ตามวันที่สร้าง · Closed = จำนวนตามวันที่ปิด **เฉพาะ Ticket ที่สร้างในช่วงวันที่เลือกและผ่านตัวกรองทั้งหมด** ดังนั้น Ticket ที่สร้างก่อนช่วงแต่ปิดในช่วงนี้ไม่ถูกนับ และ Ticket ที่สร้างในช่วงแต่ปิดหลังสิ้นช่วงไม่แสดงในกราฟ ถ้าต้องการนับ "ปิดในแต่ละวันทั้งหมด" ต้องตัดสินใจเปลี่ยนนิยามในรอบถัดไป |
| Resolution Time | Created → Closed (median) และแบบไม่รวมเวลา Waiting |
| Waiting Time | ค่าเฉลี่ยของผลรวมเวลาที่ Ticket อยู่ในสถานะ Waiting **เฉพาะ Ticket ที่เคยเข้าสถานะ Waiting** (ตัวหาร = จำนวน Ticket ที่เคย Waiting ในตัวกรอง ไม่ใช่ทุก Ticket) · หน้าจอแสดง `n` = จำนวน Ticket ที่นำมาคำนวณ และสัดส่วน % ของ Ticket ทั้งหมดในตัวกรอง · Ticket ที่ยังอยู่ในสถานะ Waiting นับเวลารอถึงเวลาปัจจุบันของ Demo |
| เวลาปัจจุบันของ Demo | ตรึงไว้ที่ 15 ธ.ค. 2026 10:00 (UTC+7) เพื่อให้ผลซ้ำได้ทุกครั้ง |

ข้อควรระวังสำหรับข้อมูลจริง (ยังไม่ได้ตัดสินใจ/ยืนยัน): คอลัมน์ Claimed/Started/Closed ที่แสดงเป็นวันที่อย่างเดียว,
Assignee ในระบบจริงเป็น LINE ID จึงต้องมีตาราง Mapping ก่อนแสดงชื่อ, กติกา Waiting กับ SLA, ข้อมูลทดสอบเก่า

## ฟอนต์ (การเรียกภายนอกเพียงรายการเดียว)

ใช้ IBM Plex Sans Thai จาก Google Fonts (ไม่บังคับ ไม่ส่งข้อมูล Ticket) ตั้งแต่ `index.html` บรรทัดที่ 9–11 หากเครือข่ายสำนักงานบล็อก หน้าจะใช้ฟอนต์ไทยในเครื่องแทนโดยอัตโนมัติ
ถ้าต้องการไม่พึ่งภายนอกเลย ให้ดาวน์โหลดฟอนต์มาเก็บใน `assets/` แล้วเปลี่ยนเป็น `@font-face`

## ความพึงพอใจ (Customer Satisfaction) — ข้อมูลจำลอง

- ส่วนใหม่: KPI `Avg Satisfaction` และ `Rated`, กราฟ Rating Distribution (5→1 ดาว), กราฟ Average Rating by Branch และคอลัมน์ `Rating` ในตาราง Ticket (แสดงเป็นดาว, ว่าง = `—`)
- ตามที่ผู้ใช้แจ้ง (ยังไม่ได้ตรวจกับ Spreadsheet จริง): คะแนนเก็บในชีต Tickets คอลัมน์ P เป็นดาว 1–5 ผูกกับ Ticket ID, Ticket ที่ยังไม่ปิดไม่มีคะแนน, คอลัมน์ P ไม่มีข้อมูลอื่นปน ต้องตรวจ Schema จริงก่อนเชื่อมข้อมูล
- นิยามใน Prototype: เฉพาะ Ticket ที่ปิดแล้วมีคะแนน · ช่องว่าง (`null`) = ยังไม่ได้ประเมิน ไม่นับเป็น 0 · ค่าเฉลี่ย = เฉลี่ยจาก Ticket ที่ให้คะแนนเท่านั้น · `Rated` = จำนวนที่ให้คะแนน และเป็น % ของ Ticket ที่ปิดในตัวกรอง
- ค่าเฉลี่ยรายสาขาที่มีคะแนนน้อยกว่า 5 รายการ (`MIN_N` ใน `app.js`) ระบุ "ตัวอย่างน้อย" และแสดงจาง ไม่ควรสรุปจากค่าเฉลี่ย
- ไม่แสดงความเห็นอิสระหรือชื่อผู้ให้คะแนน
- ข้อมูลจำลอง: อัตราการให้คะแนนและการกระจายคะแนนเป็นค่าสมมติ (สร้างจาก Ticket ID แบบคงที่ แยกจากตัวสุ่มเดิม จึงไม่กระทบตัวเลขส่วนอื่น) ไม่ใช่ผลความพึงพอใจจริงของ Dr.Orn

## สาขาในข้อมูลจำลอง

- หัว Sidebar ระบุ "Dashboard · 6 สาขา" ตามที่ผู้ใช้ระบุ (ไม่ระบุสำนักงานใหญ่ในวงเล็บ)
- 6 สาขา แสดงเป็นชื่อไทยอย่างเดียว: พหลโยธิน, ชิดลม, ราชพฤกษ์, รังสิต, รามอินทรา, เอ็มสเฟียร์ (ตรงกับค่า English ในข้อมูล: Phaholyothin, Chidlom, Ratchaphruek, Rangsit, Ram Inthra, Emsphere)
- ชื่อภาษาไทยเป็นข้อความที่แสดงบนหน้าจอเท่านั้น (`BRANCH_TH` ใน `app.js`) ค่า English เดิมใน `mock-data.js` ยังเป็นค่าที่ใช้กรองและเก็บในข้อมูล ไม่เปลี่ยน
- ข้อมูลจำลองไม่มีหมวดนอกสาขาแสดงใน UI: ตัวสร้างข้อมูลยังสุ่ม Ticket ที่ไม่ผูกกับสาขาเหมือนเดิม (เพื่อให้ตัวเลขอื่นไม่เปลี่ยน) แต่ตัดออกจากข้อมูลที่ส่งให้หน้าจอ และนับจำนวนไว้ใน `excluded` ของ `DashboardData.load()` ไม่ย้ายไปสาขาอื่น ผลกระทบต่อ KPI ระบุในรายงานส่งมอบ
- ตัวกรองวันที่: ถ้าลบวันที่ ระบบคืนช่วงที่ใช้อยู่ · ถ้า From > To สลับให้และแจ้ง · วันที่นอกช่วงข้อมูลจำลอง (`D.firstDay` ถึง `D.now`) ถูกปรับกลับเข้าช่วงพร้อมแจ้ง
